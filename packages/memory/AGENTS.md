# Working in packages/memory/

- `@hotpot/memory` is code-retrieval infrastructure only: an OpenAI-compatible embedding client, local exact vector store, incremental code index and `code_search` tool. Never read or write `MEMORY.md`, add semantic user memory, or automatically extract facts.
- Keep the package free of workspace dependencies. Runtime dependencies are limited to `zod` for the tool schema. Network I/O uses injectable native `fetch`; persistence uses Node file APIs. Do not add SQLite native extensions, LanceDB, another native database, or a database service. Keep the tool structurally compatible with core's `ToolDefinition` without importing core, so memory's standalone compilation does not pull in core sources.
- `EmbeddingClient.embed(texts, signal)` sends one batch POST to `<baseUrl>/embeddings` with `{ model, input: texts }` and Bearer authorization. Restore vectors by response `index`; validate count, indices, vectors and consistent dimensions. Pass through abort signals. Errors must never include input text or upstream response bodies.
- `VectorStore` persists at `<home>/memory/vectors/<project-key>.jsonl`. Each line is an upsert or tombstone carrying its model. Every write batch loops on `bytesWritten` until the complete UTF-8 payload is appended, then uses fsync/close and updates memory only after fsync. Keep writes serialized, validate the whole batch before appending, fold logs in order on open, skip malformed lines, and fail clearly on model or dimension conflicts. `list(namespace)` returns the latest records in that namespace.
- Record IDs are unique within a project store. Later upserts replace earlier records; tombstones remove them. Validate every removal ID as non-empty before enqueueing so accepted tombstones always replay. Search is namespace-scoped exact cosine similarity in descending score order. Do not replace it with approximate search.
- `createCodeIndexService` is lazy: construction, CLI/server assembly and project startup must not scan, open the store or use the network. Refresh the current cwd only before a search. Use content hashes to skip unchanged files, replace modified chunks and tombstone deleted ones. Fixed windows are at most 1200 characters with 200 overlap; ignore `.git/node_modules/dist/build/.hotpot`, the resolved `<home>/memory/vectors` subtree, symlinks, binary/non-UTF-8 files and files over 512KB. Index only common source extensions; exclude `.env*`, credential/password/token basenames and common private-key formats. Send at most 16 chunks per embedding request and preserve batch/vector order. Compute line numbers with one forward pass. Results use relative paths, 1-based inclusive line ranges and excerpts bounded to 800 characters.
- Persist `<project-key>.manifest.json` atomically beside the store with each file's hash and expected chunk IDs, including empty files. Reload store and manifest on every refresh, repairing missing/orphan chunks. Complete unchanged files retain only their hash; text is retained only for new, changed or incomplete files awaiting chunking.
- Coordinate every service/process for a project with an exclusive `wx` `<project-key>.lock` around reload → scan → embedding → writes. Reopen the store after lock acquisition and release the owned lock in `finally` on abort, error and audit failure. Locks and unique reclamation-intent files carry random owner tokens, refresh mtime every second, and may be reclaimed after 10 seconds without updates. Every shared-lock removal must register an intent, revalidate token and mtime before stale removal, and release only a lock still carrying the owner's token. A newly created lock must wait for all intents to clear and then revalidate its owner token before entering the critical section; if its lock was removed by an overlapping reaper, it must restart acquisition.
- `createCodeSearchTool(service)` exposes `{query, limit?}` (default 5, maximum 20), sorts by descending score and returns a clear no-match message. Index changes emit only `{files, chunks, durationMs}` through `onIndexed`; never add source text or paths to audit or telemetry payloads.
- `features.vector` defaults to false. `settings.vector.embedding` and its credentials are user-level only; never add them to the project settings allowlist or enable network/scanning implicitly. Only complete embedding configuration plus `features.vector=true` may register the tool for main/worker/task.
- Erasable TypeScript only, `.ts` extensions on relative imports, no `any`, no inline imports. Comments and README in Simplified Chinese; AGENTS in English with `AGENTS_zh-CN.md` kept in sync.
- Verify with `pnpm exec vitest run packages/memory/test packages/core/test/config.test.ts`, `pnpm typecheck`, `pnpm test`, and `pnpm exec biome check` from the repository root before committing.
