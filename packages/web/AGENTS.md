# Working in packages/web/

- Source in `src/`, tests in `test/*.test.ts`. `src/main.tsx` is the vite entry, `src/App.tsx` is the root component. `src/protocol.ts` mirrors the server-side wire contract (`packages/server/src/wire.ts`) — keep both sides in sync on any change.
- Styling: Tailwind CSS v4 (CSS-first, configured in `src/styles.css` via `@theme inline`; biome parses Tailwind directives via the root `css.parser.tailwindDirectives` setting). Base components come from shadcn/ui under `src/components/ui/` (generated code owned by this repo — normalize with `biome check --write` after adding one), icons from `lucide-react`. Theme is black/white/orange via the semantic vars in `src/styles.css`; the `@` alias maps to `src/` (kept in sync between `vite.config.ts` and `tsconfig.json`). Style conventions (color discipline, border tiers, layout, assets, streaming performance) are summarized in [STYLE_GUIDE.md](./STYLE_GUIDE.md) — follow it for any new UI.
- This package must never depend on `@hotpot/core` or other node packages at runtime: vite only bundles browser-safe code. Structural typing in `protocol.ts` mirrors the needed field subsets instead of importing them.
- State is a pure fold: `src/state/reducer.ts` reduces `WireEvent`s into `ChatState`; components render projections of that state. Keep the reducer free of DOM and React imports so it stays unit-testable in node.
- Send feedback: an idle send dispatches `send-start` before the REST call, so the user bubble, main-agent avatar and the `ProcessingIndicator` ("正在处理中" + 1-3 cycling dots) appear immediately. The optimistic user entry (`pendingUser`, id `local-user`) is replaced in place by the durable `user_msg`; `send-cancel` removes it for builtin replies / create failures / request errors, and `turn(end)` cleans up leftovers. The indicator renders only while `turn === "running"` and always after the last main-agent output line.
- LLM-facing prompt text is English; code comments in Simplified Chinese.
- Plan flow: `internal_msg` is ignored by the reducer; `plan(drafted)` carries `messageIds` for the assistant messages holding the plan text, and the reducer removes them (also suppressing later-arriving logs) so only the plan card is shown.
- M4: the reducer folds `inbox/spliced` into `state.inbox`; `applyInboxSnapshot` overwrites both queues from `GET /api/sessions/:id/inbox` after consumption. The composer autocompletes prompt templates fetched from `GET /api/sessions/:id/prompts` (sending stays `/name args`; the server expands). Keep `protocol.ts` in sync with the new M4 event variants.
- Agent panel card status: the done/failed state is driven solely by the durable `agent_end` log event (mirrored in `protocol.ts`), with `log(error)` marking failed immediately and never reverted; `turn(end)` does NOT flip agent status anymore. The `[FAILED]` string heuristic on `tool_result` was removed — failure formats (`[worker-1 failed]` / `[FAILED] task-1:`) are LLM-facing only.
- 会话区本地路径可点击（v1）：`StreamdownMarkdown` 覆写 `inlineCode`（行内 code 恰为绝对路径 → `LocalPathLink`）并在 p/li/td/th/h1-6/blockquote 经 `linkified()` 注入 `LinkifyText` 链接化裸路径；`LinkifyText` 递归 children 时跳过链接（按 href prop，streamdown 的 `<a>` 是 button 组件）/code/pre 子树。user 气泡同走 `LinkifyText`。识别规则在 `src/lib/local-path.ts`（Unix 绝对路径含 CJK 段、URL/版本号/中文顿号式 slash 排除），与服务端扩展名白名单保持同步。点击经 `OpenLocalPathContext` 调 App 的 `openLocalPath`（fs/stat 判型 → 同路径复用 tab 只激活），失败落本地 notice。右侧面板已 tab 化（`AgentPanel`：固定 Agents + 可关闭文件 tab）：无 running worker 时因文件 tab 也展示、tab 全关即收起（无 worker 时头部 X = 关全部文件 tab）。文件 tab 内容在 `FileViewer.tsx`：文件夹 = 面包屑 + 单层列表导航（点击 dir 进子级、点 file 新开 tab）；文件 = 图片（`fetchViewerRaw` → objectURL）/文本（fs/read → pre）/白名单外占位三态。fileTabs/activePanelTab 是 App 本地瞬态（不进 reducer，类比弹窗态），切换会话清空。composer 底部附件按钮后有「当前工作区」入口（Folder 图标 + 会话 cwd 文件夹名，hover tip「当前工作区」）：点击经同一 `openLocalPath` 打开 cwd 文件树 tab；welcome/无会话态不渲染。
- M5 composer and queue: while a turn runs, plain sends are queued (server enqueues into next-turn and persists `inbox/spliced`); the pinned QueueBar above the composer lists next-turn items — clicking an item steers it (moves to next-step, 409 unless running) and ✕ removes it, while next-step items render as "注入中". Permission selector (`PermissionSelect.tsx`) switches `readonly` / `ask-on-dangerous` / `full` via `PUT /permission`, read from the `permission` wire event and seeded by `GET /permission`; the reducer holds it in `state.permissionMode`. Text attachments upload through `POST /uploads` and are appended to the message as `@<absolute path>`; `@` in the composer autocompletes workspace entries from `GET /fs/ls`. Builtin slash commands (`/help`, `/permission`) answer `200 {reply}` and render as local notice bubbles (`notices` in App, never durable). Sessions are still created lazily on the first message (see the workspace bullet below). The composer also hosts a live plan bar directly above it: `state.lastTodoAgentId` points at the most recent `todo/set` agent and the bar renders that todo snapshot with a progress fraction (cleared by `turn(start)` together with `todosByAgent`).
- Workspace browser: `GET /api/workspaces` is the sidebar source of truth (`WorkspaceWire[]`, array order = display order). `SessionList` groups sessions by each workspace's `sessionIds` (pure helper `src/lib/workspaces.ts`), renders unowned sessions in a trailing 「未分组」 section, persists collapse state in `hotpot.workspaceCollapsed` while auto-expanding the current/draft group, and reorders workspaces by dragging group headers (`PUT /api/workspaces/order`; App applies the order optimistically and refreshes to roll back on failure). 「添加工作区」 calls `POST /api/directory-picker/pick` directly (no intermediate dialog; `{path:null}` = canceled) and registers the chosen path with `POST /api/workspaces` — a repeated path returns the existing record (`created:false`). Only a 501 / `picker-unavailable` response (`PickerUnavailableError` in `api.ts`) opens `WorkspacePickerDialog` in `startInManual` mode for manual path input. Rename/delete rejections are surfaced inline by the sidebar dialogs; deleting a workspace only unregisters it, so its sessions fall into 「未分组」.
- Draft sessions (temporary, never persisted): clicking the sidebar's top 「新建会话」 creates a draft bound to 「未分组」; the per-workspace 「+」 creates one bound to that workspace. At most one draft exists — creating another replaces it. The draft renders as a 「新会话」 row in its group (`DraftRow`), selects the welcome composer, and its permission choice lives in `DraftSession.permissionMode`. The first message calls `createSession({ workspaceId: draft.workspaceId ?? null, permissionMode })`: a string attaches to that workspace; explicit `null` skips the server's cwd auto-attach so the session lands in 「未分组」; omitted `workspaceId` keeps auto-attach (CLI behavior). After creation the draft is cleared and the real session is named from the first prompt. Because no session exists yet, the composer's permission and attachment controls stay enabled: draft uploads go to `POST /api/uploads` (`uploads/drafts`), and the chosen permission is applied when the session is created.
- Icon-button tooltips: an icon-only button (icon child + `aria-label`, e.g. 「添加工作区」 and the per-workspace 「新建会话」) shows its tooltip with `side="top"` and `sideOffset={0}`, so the bubble sits directly above the SVG with no gap. Never anchor icon tooltips to the side of the button. `src/components/ui/button.tsx` must stay a `forwardRef` component: Radix `Tooltip`/`DropdownMenu` triggers use `asChild` and need the child ref to anchor the popup — a plain function component loses the ref and the bubble silently renders at the viewport origin (0,0), looking like it never appears. `src/components/ui/tooltip.tsx` keeps the tooltip controlled and closes it from `TooltipTrigger` on `pointerdown`/`click`, so clicking a button dismisses its tip immediately instead of waiting for the pointer to leave.
- API authentication is bootstrapped by `src/auth.ts`: `main.tsx` moves the initial `?token=` into session storage and removes it from the URL. All REST calls use `authenticatedFetch`; EventSource URLs use `withApiToken` so reconnects keep `access_token`.
- Erasable TypeScript only, `.ts`/`.tsx` extension on relative imports, no `any`, no inline imports. Sole exception: `Markdown.tsx` uses one `React.lazy` dynamic import to code-split the streamdown renderer (shiki/katex/mermaid) out of the first-load chunk — keep `StreamdownMarkdown.tsx` imports static.
- Markdown rendering: `Markdown.tsx` is a thin `{text, streaming?}` wrapper (empty text → null, memo, Suspense fallback null); `StreamdownMarkdown.tsx` owns the streamdown renderer with the code/math/mermaid/cjk plugins. Pass `streaming` while a turn is in flight (`MessageBubble` does), settled text renders in static mode.
- Verify with `pnpm test`, `pnpm typecheck`, and `pnpm exec biome check` from the repo root before committing.
