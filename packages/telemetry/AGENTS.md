# Working in packages/telemetry/

- `@hotpot/telemetry` is the M5 anonymous telemetry client: strict event schema, error sanitizer, install ID, batching client, per-turn collector and the shared runtime. `cli`, `server` and the planned `benchmarks` runner may import it; `core`, `orchestrator` and `ai` must never import it.
- Dependency direction is fixed: `cli/server/benchmarks → telemetry → core → ai`. Import core through the package root (`@hotpot/core`). Never import `@hotpot/cli`, `@hotpot/server` or `@hotpot/orchestrator`; the collector observes orchestration events through the structural `ObservedOrchestrationEvent` type instead, so telemetry stays decoupled from the orchestration layer.
- Strict schema first: every event object in `src/events.ts` is `.strict()` under `SCHEMA_VERSION = 1`, so unknown fields are rejected rather than stripped. Adding a field means updating the zod schema, the hand-maintained interface, `test/events.test.ts` and the whitelist table in `README.md`. Treat any field that could carry user content as forbidden, even when optional.
- Never emit user content: no prompt/reply text, tool input/output, file content, file paths, commands, URL query strings, user names, repository names or task titles. Read only metadata from the session JSONL (`type`, `ts`, `usage`, `model`, `tier`, `agentId`). `assistant_msg.content` is read only to identify tool-call block names; never emit its text, tool inputs or tool outputs. Error text must pass through `sanitizeErrorMessage` before it leaves the process.
- Sanitizer ordering is load-bearing: code fences → extract URLs to placeholders → emails → Windows drive paths → UNC paths → absolute POSIX paths (keeping the matched prefix) → restore normalized URLs (http/https/ws/wss keep scheme+host+pathname; other schemes become `<path>`; an unparseable URL becomes `<url>`) → collapse whitespace → truncate (500 by default). Do not reorder these rules without re-checking every case in `test/sanitize.test.ts`. Fail closed: return `""` when parsing fails instead of forwarding raw text.
- Never throw or block. `enqueue` is synchronous and only touches the in-memory queue; `flush`/`close` serialize, swallow every failure and never reject; retry sleeps and the flush interval are `unref()`'d so they cannot keep the process alive. The collector treats an unreadable or corrupt session log as empty and a failed fold as a zero-total `turn_end`; the runtime returns `null` for disabled or misconfigured telemetry instead of throwing. Callers rely on `null` meaning "bypass not enabled"; keep that contract.
- Endpoint resolution order is settings > `HOTPOT_TELEMETRY_ENDPOINT` > `DEFAULT_TELEMETRY_ENDPOINT`, and the source constant stays empty by default. `settings.telemetry.endpoint`, when present, must be a non-empty string (schema `min(1)`); an empty settings value is a validation error, not a no-op. Only the env/source fallback can be empty: an empty resolved value or a non-`http(s)` URL makes the runtime return `null` (telemetry disabled). A token is a literal or a whole-string `$ENV` reference; a missing env value means "no Authorization header", not an error. Do not add partial-string interpolation.
- Settings are user-level only: `telemetry` is absent from `projectSettingsSchema` in `packages/core/src/config/config.ts`. Never add it there; a repo-controlled endpoint/token would redirect reported data and credentials to an attacker.
- Install IDs live at `<home>/telemetry/install-id` for `kind: "user"` and `<home>/telemetry/benchmark-install-id` for `kind: "benchmark"`. Resolve home through `resolveHome` from core; do not duplicate the param > `HOTPOT_HOME` > `~/.hotpot` rule. ID writes are best-effort: a read-only home must not fail a turn.
- Erasable TypeScript only, `.ts` extension on relative imports, no `any`, no inline imports; comments and README in Simplified Chinese, AGENTS in English.
- Verify with `pnpm test`, `pnpm typecheck` and `pnpm exec biome check` from the repo root before committing.
