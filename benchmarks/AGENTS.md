# Working in benchmarks/

- `@hotpot/benchmarks` is a development/evaluation tool. `cli` and `server` must never import it, and it must not enter the shipped tool bundle. It may import `@hotpot/core`, `@hotpot/orchestrator`, `@hotpot/ai` and `@hotpot/telemetry`.
- Never reimplement SWE-bench scoring. Patch generation is ours; pass/fail comes only from the official `swebench.harness.run_evaluation` report (`resolved_ids` / `unresolved_ids` / `empty_patch_ids`). A missing report or non-zero harness exit is a failure with the log path, never a pass.
- The M5 benchmark agent is patch-only: plain checkout, no repository dependency installation, no repository test execution, no commit. Keep the prompt suffix in `src/cli.ts` and the session-runner setup in `src/agent-runner.ts` consistent with that baseline.
- `src/runtime-profile.ts` is the single source of truth for how a run is assembled: feature flags, `maxParallelTasks`, plan auto-approve, permission, timeout and `patchOnly`. Never re-hardcode those values in `agent-runner.ts` or `cli.ts`, and never set `report.patchOnly` by hand. Any new assembly (capability profile, ablation) is a new profile with a distinct `label`, so the manifest records it.
- `src/manifest.ts` records experimental conditions, so keep it free of credentials: store `provider`/`model`/`baseUrlHost`/`baseUrlPath` only, never `apiKey` and never a full `baseUrl` (it may carry a query string). Task-set identity is a hash (`idsHash` for the selected set, `tasksetHash` for custom task content), not a list. `status: "running"` written at start means the run did not finish; reports from such a directory are not conclusions.
- `describeManifestDiff` defines comparability: suite, runtime profile, any model fingerprint, main tier, git commit, package version, selection hashes, dataset/split and evaluation mode. Two runs that differ on any of these must not be compared, and every report must embed the manifest it was produced under.
- `WorkspaceProvider` (`src/workspace.ts`) is the seam for a future container runner. The upper runner must only use `prepare(instance) -> { cwd, cleanup() }`; do not leak checkout details (cache paths, git commands) into `cli.ts` or report code. `CheckoutWorkspaceProvider` uses one cached clone per repo plus a detached `git worktree` per instance; cleanup removes the worktree and prunes it.
- `capturePatch` must run `git add -A -N -- . ':!node_modules' ':!.hotpot'` then `git diff --no-color HEAD` with the same pathspec. Diffing against `HEAD` (not the index) keeps changes the agent staged with `git add`; untracked files must appear in the diff, while `node_modules` and `.hotpot` must not. An empty patch is a valid prediction and is preserved as an empty string.
- Approval is explicit allow-all, audited: build a plain `ApprovalChain`, `use(allowAllHandler)` (or `use(async () => "allow")`), wrap it with `createAuditedApprovalChain` so `approval/asked` + `approval/decided` land in the session log, and auto-approve plans via `onPlanApproval`. Do not route benchmarks through `permission.mode`; the explicit allow-all chain keeps runs zero-interruption regardless of user settings.
- Real runs use a temporary `HOTPOT_HOME` (mkdtemp per instance) so user sessions and the user telemetry install ID are untouched. Tests must not read `~/.hotpot/settings.json`; inject `Settings` and a scripted adapter.
- Reports contain instance ids, pass/fail, token counts, durations and sanitized failure reasons only. Never write prompts, replies, patches, file contents or raw absolute paths. Sanitize every failure reason through `@hotpot/telemetry`'s `sanitizeErrorMessage` before it reaches `report.json`/`report.md`. Report metrics are `mean`/`median`/`p90` (a single long-context instance skews the mean), `tokens.byTier` with `tierCoverage`, and `tokensPerResolved` (`null`, not `0`, when nothing resolved).
- Failure classification lives in `src/failure.ts` (`classifyFailure`) and is the single definition of the enum. `buildReport` computes it once per instance and both `report.json` and telemetry read that value; never re-derive a class elsewhere, and never send a free-text failure reason to telemetry.
- Benchmark telemetry is a side channel: `kind: "benchmark"`, benchmark install ID, no content fields, and it must never throw into the runner (`createTelemetryRuntime` returning `null` means "disabled, skip"). It is sent as **run-level batches** (200 events per POST) after the run finishes, never one request per instance: the server's `/ingest` is rate limited to 60 req/min and per-instance sending silently drops ~10% of a 300-instance run. Every event carries the run's comparability context (`runId`, `commit`, `commitDirty`, `model`, `tier`, `patchOnly`, `tasksetHash`) plus `errorClass` and `byTier`; `runId` is what lets the server fold N events into one comparable run. The returned `TelemetryDelivery` must be written into `report.json` (`telemetry`) — a dropped batch has to be visible, not swallowed.
- Tests are hermetic: scripted adapter, temp git repos, temp HOME, no network/Docker/SSH. Local and remote evaluation are covered only through `buildEvaluationCommand` and `parseOfficialReport`; do not add tests that shell out to `ssh`, `docker` or `swebench`.
- Sharding, resume and merge are in-repo, deterministic and comparable-or-nothing. `src/shard.ts` interleaves by index (`idx % count === index`), so the same selection plus the same flags always yield the same subset and all shards together cover the parent set exactly once; never replace it with slicing or random sampling. A sharded run records `selection.shard` plus `parentIdsHash`/`parentCount`, and `manifestForComparison` normalizes to the parent view — `parentIdsHash` is the only thing that makes two shards comparable, so `merge` must compare normalized manifests and must refuse both incomparable shards and any instance that appears in two shards (it would be counted twice in `passRate`). `--resume` reuses the existing `runId`, reuses each finished `(instance, attempt)`'s official verdict and patch, re-evaluates only the newly produced predictions (`official/attempt-<k>/pending-predictions.jsonl`), and must reject a manifest whose conditions no longer match. `combineOfficial` is what keeps reused verdicts from being re-judged as failures.
- The default suite is data, not a `--limit`: without `--limit` or `--instance-ids` the run uses `suites/lite10.json` (10 fixed ids, loaded by `src/suites.ts`). Never replace it with `--limit 10` — `limit` shuffles the instance file with a seed and then slices, so a different export file yields different questions and two runs can no longer be paired question-by-question. A missing id must fail with a fix-it hint (`selectSelection`), not a bare `unknown instance id`. Adding a suite means adding a JSON file, not a branch in `cli.ts`.
- Repetition is a first-class dimension, never a loop that overwrites results. `--repeat k` defaults to 3: one attempt on 10 instances has the same spread as the feature being tested. Keep the attempt number on `InstanceResult.attempt`, in `predictions-a<k>.jsonl` (one file per attempt: the official harness indexes by `instance_id`, so a second row for the same instance in one file overwrites the first), in `official/attempt-<k>/` plus a `-a<k>` run id, and in `manifest.repeat` (part of comparability — k=1 and k=3 are different experiments). Report semantics: `total` is the instance count, `passed` is the number of passing attempts, `passRate` is the per-attempt average, `resolvedInstances` is the count resolved at least once, `repeat.passRateByAttempt` is the spread, `repeat.flakyInstances` counts instances with a pass rate strictly inside (0,1), and `failures` lists only instances that never passed. Never use pass@k for version comparison: it hides a stability drop.
- Resume, merge and telemetry all key on `(instanceId, attempt)`. `progressKey` is the single definition; a reused patch must come from the same attempt (`patchEntries`), and an empty patch must still be written — dropping it makes the harness treat the question as never run. Merge must reject overlapping `(instanceId, attempt)` pairs and mismatched `repeat`, and must rebuild one official report per attempt rather than mixing attempts into one verdict list.
- `src/doctor.ts` must stay read-only and bounded: subprocess probes with a timeout, network probes only when `--offline` is absent, a `fail` for anything that would definitely cost a run (missing key, missing docker/swebench, missing instance file, too little disk) and a `warn` for anything that only weakens the conclusion (dirty worktree, telemetry off). Every `fail` needs an executable `fix` line, and `doctor` exits non-zero when anything failed so it can gate a scripted run.
- `scripts/export_instances.py` must set `HF_ENDPOINT` before importing `datasets`, keep the seven exported fields, and normalize `FAIL_TO_PASS`/`PASS_TO_PASS` to string arrays. `selectInstances` must stay deterministic for a given seed and must reject unknown explicit instance ids.
- `src/experiment/` is the experiment ledger (`pnpm exp`), and the ledger lives in the main worktree (`docs/experiments/registry.json`) — never inside a branch worktree, or experiments drift with the code and `new` cannot be trusted to run only from the main checkout. `new` creates two worktrees: `exp/<slug>` on `baseCommit` and a detached baseline worktree at the same commit, so the baseline can never move; run output goes to `benchmark-runs/experiments/<slug>/` outside both, because `close` deletes the worktrees. `record` must refuse a run whose manifest `status` is not `completed`, whose worktree was dirty, whose commit is not the recorded `baseCommit` (base) or the head worktree HEAD, whose `repeat` differs, or whose conditions differ from the other variant after `describeManifestDiff(..., { ignoreIdentity: true })` — commit and package version are the only fields allowed to differ between base and head. `comparison.verdict` is a spread test (`max(observed spread, 100/instances)`), never a significance test: it may not silently drive a decision, and pass@k stays out of it. Render `<slug>.md` from the record instead of parsing markdown, so machine fields have exactly one source.
- `src/experiment/run.ts` is the only driver for two-variant runs. It shells out to `pnpm bench swebench` in each worktree with `--suite` taken from the record (never rely on the CLI default: a future default change would silently change the question set) and an absolute `--output` under `benchmark-runs/experiments/<slug>/`. Preflight must reject missing instance files, dirty worktrees, a baseline worktree HEAD that moved off `baseCommit`, and an existing completed run whose commit or `repeat` no longer matches. Stream every child process chunk to both the console and `<runDir>/exp-run.log` (runs take hours; terminal scrollback is not a log). On any non-zero exit stop immediately and register nothing. A rerun skips completed variants and adds `--resume` for unfinished ones; `--force` renames the old directory to `.bak-<timestamp>` instead of overwriting it. Automatic registration must call the same `registerRun` as `exp record` — never a simplified copy — and must clear a stale `comparison`/`telemetry` when evidence changes.
- `src/telemetry-read.ts` is the read side and is deliberately separate from the ingest client: reads use an admin cookie from `POST /api/v1/login`, ingests use `Bearer ingestToken`. Credentials come only from environment variables, never from CLI flags, files or logs; the cookie lives in memory for one command. Every response is validated against a zod schema (an older server missing `instances`/`attempts` must fail loudly, not produce a plausible pass rate), and queries always carry `kind=benchmark&from&to` because the server filters on event time and limits the run list to 200 rows. `src/experiment/pull.ts` reconciles remote summaries against local `report.json` per `runId` (instances, attempts, passed, pass rate, resolved, flaky, flaky id set); `missing`/`mismatch` are evidence problems, not command failures, and must be visible in both `telemetry.json` and the ledger's `telemetry` summary. `pull` never rewrites a run result.
- Erasable TypeScript only, `.ts` extension on relative imports, no `any`, no inline imports; comments and README in Simplified Chinese, AGENTS in English. `.py` comments are Chinese; LLM-facing prompts are English.
- Verify with `pnpm test`, `pnpm typecheck` and `pnpm exec biome check .` from the repo root before committing.
