# hotpot-agent Star 增长计划（2026-11 起，8 周）

> 唯一目标：GitHub star。北极星之外的安装量、留存、社区活跃只在「影响 star」时才做。
> 原因：star 是陌生人一次点击就能给的投票，它只取决于两件事——**有没有人看到**，以及**打开仓库的 30 秒里有没有被说服**。

## 1. 基线（2026-11-07 实测）

| 项 | 现状 | 对 star 的影响 |
|----|------|---------------|
| star / fork / watcher | 11 / 1 / 0 | 起点，等于零 |
| 建仓时间 | 2026-10-08 | 一个月，仍在「新项目」红利期 |
| 版本 | v0.2.0，npm 已发布 | 可验证，不是 PPT 项目 |
| GitHub description | `a helpful code agent` | 无信息量，搜索与分享卡片都吃亏 |
| topics | 仅 `agent` | 不进任何 topic 列表页，损失被动流量 |
| README 首屏 | 文字 + 架构图 | 无 GIF、无成本数字，手机端 3 秒划走 |
| 硬数据 | SWE-bench Lite 300 全量 168/300（56.0%，Kimi 档位，patch-only）；Lite 10 题基线 9/10（DeepSeek 档位，10 题约 $4.62） | 唯一可传播的钩子，目前埋在第 100 行以后 |

> 2026-11-08 补入 Lite 300 全量结果（`docs/benchmark-reports/2026-11-08-swebench-lite300.md`）。两次跑批模型档位不同、不可直接对比；对外传播用哪组数字需要重新评估，下文渠道策略暂不改动。

判断：**产品够格被 star，包装完全不合格。** 当前 11 star 不是没人感兴趣，是没人看得见，看见的也没被首屏说服。

## 2. Star 从哪来（先算清账）

行业经验值：一次渠道爆发占新 star 的 60~70%，长尾搜索与列表页占 20~30%，社区口碑占 10%。

| 来源 | 机制 | 单次量级 | 可控性 |
|------|------|---------|--------|
| Hacker News 首页 | 单日 star 增速冲进 GitHub Trending，二次放大 | 100~400 | 低（一次机会） |
| 中文技术周刊（阮一峰 / HelloGitHub） | 编辑推荐，读者信任度高、转化率高 | 50~150 | 中（可投稿） |
| V2EX / 掘金 / 即刻 | 中文开发者首波，评论互动带动二次曝光 | 30~80 | 中 |
| X / Reddit | 视频与数字类帖子长尾传播 | 20~60 | 中 |
| GitHub topic 与搜索 | `code-agent` `cli` 等 topic 列表的被动流量 | 持续 | 高（改配置即可） |

**结论：把 80% 的精力压在「一次爆发」上，而不是均匀铺 10 个渠道。** 均匀发布的结果是每个渠道都不够热，哪个都上不了榜。

## 3. 转化漏斗与目标

```
80,000 曝光（渠道阅读/展示）
   ↓ 10%
 8,000 打开仓库
   ↓ 10%
   800 star
```

| 环节 | 4 周 | 8 周 | 说明 |
|------|------|------|------|
| star | 150（保底）/ 350（争取） | 400 / 800 | 低于 100 说明首屏有问题，不是渠道问题 |
| 仓库访问 | 3,000 | 8,000 | 用 GitHub Traffic 页核对 |
| 访问→star 转化 | ≥5% | ≥8% | 首屏改造的唯一验收指标 |
| 单日峰值 star | ≥60 | ≥100 | 上 Trending 的门槛参考 |

## 4. W0：门面改造（11-08 ~ 11-15，决定成败）

star 的转化几乎全部发生在首屏。逐项验收：

| # | 事项 | 验收标准 |
|---|------|---------|
| 1 | **README 首屏重写** | 首屏（手机一屏内）必须同时出现：一句主张、一张 15 秒 GIF、一行 `npm i -g hotpot-agent`、一个数字「10 题 $4.62」。当前架构图下沉到第 3 屏 |
| 2 | **GitHub Social Preview 图** | 1280×640，含 logo、一句主张、成本数字。所有分享卡片都用它，这是免费的二次曝光位 |
| 3 | **description + topics** | description 改为一句话卖点；topics 补 `code-agent` `ai-agent` `cli` `typescript` `llm` `developer-tools` `terminal` `anthropic` `deepseek` |
| 3 | **成本对比柱状图** | 一张可直接截图的图：三个模型档位的「单题成本 vs 通过率」。转发的最小单元不是文章，是这张图 |
| 4 | **90 秒 Demo 视频 + GIF** | 复杂任务出计划 → 人工改一行 → 批准 → 并行 worker → Web 面板看 token 账 |
| 5 | **英文 README 同步** | 海外渠道只认英文首屏，数据与中文一致（AGENTS.md 已要求两版同步） |
| 6 | **加星引导** | README 结尾一句话说明「如果它帮你省了钱，给个 star」，不做弹窗式乞求 |
| 7 | **修掉重连缺陷** | 首发流量会刷新页面，撞上 README「已知问题」里的掉窗重连不重建状态即流失（虽不直接影响 star，但直接影响评论口碑） |

补充判断：**首屏不要放架构图。** 架构图说服的是已经想 star 的人，劝退的是还没决定要不要看的人。

## 5. 三个传播资产（按 star 效率排序）

### A. 成本对比图（最高优先级）

- 一张图：x 轴通过率，y 轴单题成本，三个点代表三档模型。
- 配一句可引用的结论：`9/10 通过，单题 $0.46，脚本可复现。`
- 为什么有效：竞品都在讲能力，没人把账摊开。这张图是我们唯一能被别人转发的理由。

### B. 90 秒 Demo

前 5 秒必须出现「终端里一句话进去、代码出来」的画面。star 是冲动决策，慢热的开场没有第二次机会。

### C. 一页对比表

与 Claude Code / Codex CLI / Aider / Cline / OpenHands 并列，只写可验证差异：部署形态、模型自由度、成本可见性、是否本地 Web UI。**不写「更好」，只写「不同」**——技术读者的信任来自克制。

## 6. 八周排期（围绕一次爆发设计）

| 周 | 动作 | 目标 |
|----|------|------|
| W0 11-08~11-15 | 第 4 节 7 项全部完成；资产 A/B/C 出稿；给 3 位朋友做冷读测试（只看首屏，说出这项目干什么） | 首屏被正确复述 ≥2/3 |
| W1 11-16~11-22 | **爆发周**。周二 08:00 PT 发 Show HN；同日 12:00 北京时间发 V2EX 分享创造；周三掘金长文；周四 X thread + Reddit r/LocalLLaMA；周五给阮一峰周刊提 issue | 单周 star ≥120，至少一天进 Trending |
| W2 11-23~11-29 | 周刊二次曝光（若被收录）；Dev.to 英文 cross-post；提 2 个 awesome-list PR；修补评论里被指出的问题并回复 | 周 star ≥60 |
| W3 11-30~12-06 | 对比评测文（Aider / Cline 同题同模型）；投稿 HelloGitHub | 周 star ≥50 |
| W4 12-07~12-13 | 发 v0.3（路线图兑现），changelog 当内容发；公众号复用长文 | 周 star ≥40 |
| W5-W8 | 双周发版 + 每两周一篇「成本实验」短文（换模型、换编排策略各跑一次，只发图和结论） | 周均 ≥40，累计 400 |

**排期纪律**：爆发周内所有渠道错峰 24 小时，每条内容重写标题与前两段。同一段文案出现在 5 个平台，读者会判定为推广并划走。

## 7. 渠道动作清单

| 渠道 | 具体做法 | 关键约束 |
|------|---------|---------|
| Show HN | 标题格式 `Show HN: A code agent that routes cheap models first – 9/10 SWE-bench Lite at $0.46/task`，正文第一段讲清是什么，第二段给成本口径，第三段给复现命令 | 美西时间周二至周四上午；发完 2 小时内必须在评论区答疑，回复率决定排名 |
| V2EX 分享创造 | 标题避免夸张，正文写「我为什么做这个 + 实测数据 + 已知缺陷」 | 不带任何营销词；贴仓库链接前先说清成本口径 |
| 掘金 | 长文《同一批任务，我把 code agent 的单题成本压到 $0.46》 | 标题带数字；正文放可复现脚本 |
| 即刻 / X | 15 秒 GIF + 一句数字，不写长文 | 视频优先于文字 |
| Reddit r/LocalLLaMA | 只发数据贴：换 DeepSeek 后的成本与通过率 | 不带 star 请求，评论区自然会问 |
| 阮一峰周刊 | GitHub issue 提交，一句话介绍 + 链接 | 每周五前提交，格式照往期 |
| HelloGitHub | 官网提交项目，附一句话卖点与截图 | 月刊周期，提前两周 |
| awesome-lists | 提 PR 到 code-agent / ai-agents 类清单 | 严格按清单格式，一个 PR 只加一项 |

## 8. 红线（比技巧重要）

1. **不买 star、不进互 star 群、不用机器人转发**。GitHub 有 star 异常检测，被抓一次长期污点，且技术圈传播速度极快。
2. **不喊「最强 / SOTA」**。n=10 经不起追问，被评论区拆穿会反噬 star。「可复现的一次实测」比「最强」更有说服力。
3. **成本口径写全**：模型版本、是否非高峰价、是否含重试、patch-only 基线、样本量。含糊的数字会在 HN 评论区被逐条质询。
4. **不隐藏已知缺陷**。README 的「已知问题」是这个项目最值得保留的部分，技术读者会因此更信任其它数字。
5. **不刷 issue 制造活跃假象**。star 增长曲线干净比数字好看更重要。
6. **爆发周只打一次**。HN 同一项目复投要间隔数月，失败就没有第二次。

## 9. 投入与判据

- 人力：约 0.5 FTE × 8 周（内容 + 素材 + 首屏工程），现金投入 0。
- 主要时间成本在资产 A 的跑批与口径核对，约 2~3 天。

W1 结束复盘：

- **加码**：单周 star ≥120 或进过 Trending → W2-W4 内容加密到每周 2 篇，增加 X 与 Reddit 频次。
- **改首屏再发**：仓库访问 ≥1,500 但转化 <3% → 问题在首屏，不在渠道。回去改 GIF 与前 3 行，渠道不追加。
- **换主张**：访问 <500 → 内容是没被推到目标人群，换渠道与标题角度，不动产品。

> star 是放大器，不是修复器。首屏讲不清价值时，投多少渠道都只是在加速划走。
